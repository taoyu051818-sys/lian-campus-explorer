# 图书馆 Blender 建模资产

这是一版根据建成照片重建的外景模型。十九层塔楼与四组低层裙楼的体量组织、分区格栅、实体横带、斜切顶部及阅读庭院有参考依据；尺寸、各瓣位置、退台和格栅模数仍为估算。没有单体施工图、点云或 BIM，因此不称为精确复原。院内暂用低矮种植池示意绿化，不含室内或虚构房间。

## v0.29.3 航拍体量校正

纠正 v0.29.2 把“五个花瓣体量”解释为“五组低层裙楼”的错误：照片中为一座塔楼和四组低翼。名称按用户正面航拍的画面方向定义，不表示地理方位；模型 +X 在此机位投影到画面左侧。

| 楼翼 | 主露台标高（米） | 内层屋顶标高（米） | 位置与形态 |
| --- | ---: | ---: | --- |
| front-left | 20.0 | 25.0 | 画面左前，白色内层屋顶与低露台 |
| front-right | 20.0 | 24.8 | 画面中前，白色内层屋顶与低露台 |
| right-garden | 13.8 | — | 画面最右，低花园翼 |
| rear-garden | 15.0 | 20.0 | 右后方，上层绿化平台和下层露台 |

前排的主要楼层线接近齐平，高低关系由内层屋顶、低露台与外圈斜冠共同形成。移除多余后翼，扩大塔楼宽度，并重排入口与中央玻璃天窗。裙楼不再由同一种三角形复制旋转，而是分别用照片控制点定义曲线轮廓；三档 LOD 共享同一条屋顶曲线。模型页默认「实拍视角」，以近似照片机位检查左右位置和轮廓。

控制点、相机、屋顶标高均为照片拟合。`design.json` 保留取点坐标与假设，便于后续依据测绘修正。场地坡度和遮挡区域尚未测绘，不据单幅照片宣称精确尺寸。

## 2026-09-29 实拍立面修正

按用户提供的入口近照、正面航拍和仰视全景重新分区。塔楼不使用几何纹样：玻璃、灰色窗间板、浅金色水平遮阳条分别建模。裙楼每层的宽实体带、玻璃槽和局部格栅分别占据独立高度区间。横带估算高 1.12 米、外挑 0.86 米；格栅随各层层高调整，顶端留出约 0.62 米玻璃槽。尺寸用于控制照片中的比例，未经测量。

`clearGlazingZones` 明确定义各楼翼和楼层的玻璃区域，替换原来的随机索引缺口。近／中景使用裁切后的真实格栅构件，远景纹样面遵守同一分区；花园翼底层完全不覆盖花纹。入口改为内凹弧形玻璃连廊、实体招牌带和轻薄门雨棚，低矮花园翼依据航拍移至入口两翼侧边，前排屋顶增加白色平台与中央玻璃天窗。隐藏面与平面位置仍含估算。新增的入口碰撞体独立于装饰网格。

`test:library` 直接解码三个 GLB 的实际顶点，检查格栅没有跨入实体／玻璃带、灰色窗间板没有占满塔楼窗户，以及花园翼底层没有格栅。实拍照片仅作观察依据，不随资产公开。

## 编辑与导出

使用 Blender **4.5 LTS**（本次 4.5.9）。`design.json` 是位置、米制尺寸及来源的参数源；`build.py` 构建分组网格、倒角檐口、玻璃与外置格栅、庭院开口，并保存可继续手工编辑的源文件。

```sh
blender --background --factory-startup --python authoring/library/build.py
node authoring/library/compress.mjs
npm run build
npm run test:library
npm run test:physics
```

压缩脚本用 npx 获取固定版本 `@gltf-transform/cli@4.2.1`；pnpm 环境可加 `--pnpm`。首轮需要联网。常规网页构建直接读取已提交的 GLB，不运行 Blender 或压缩器。

可加 `-- --render` 输出 整体、裙楼层次、入口及塔楼立面四个预览图（`preview.png`、`roof-heights.png`、`entrance.png`、`tower-facade.png`）。中文招牌读取 macOS 的华文黑体；其他系统先把 `LIBRARY_FONT` 环境变量设为本机 CJK 字体路径。文字在源文件保存前转换为可编辑网格，模型不嵌入字体文件。没有中文字体时会提示并省略中文文字，保留英文标识。

生成的 `library.blend` 保留三档集合、按体量／材质分组的网格、PBR 材质、已打包的远景纹样、相机和工作灯光。打开时只显示 LOD0；可在 Outliner 中启用其他集合。`.blend` 和预览图不进入 Git，避免每次重新生成使仓库膨胀；本次交付另外提供源文件包。源脚本及参数均在 Git 中。

若在 Blender 中手工编辑，从指定 LOD 集合选择对象导出 glTF Binary，保持米制单位、原点和 Y-up；不要导出工作灯光及相机。三个文件分别覆盖 `public/models/library/library-lod0.glb`、`library-lod1.glb`、`library-lod2.glb`，再运行压缩脚本刷新三角面数、大小及 SHA-256。修改轮廓后还需同步清单中的碰撞轮廓，并重新 bake/test。

## 运行时约定

- Blender 为 Z-up；GLB 转为 Y-up，局部 +Z 朝建筑后方。校园配准只在 `src/library-registration.ts` 和 GLB 根节点施加一次。
- LOD0 保留近景格栅、门头文字及塔楼构件；LOD1 减少曲线采样和格栅层数；LOD2 用烘焙纹样面代替细格栅。当前约 57.4 / 27.4 / 5.5 万三角面，0 / 240 / 650 米切换，12% 滞回。
- 三档 GLB 采用 Meshopt，Three.js GLTFLoader 通过同版本内置 MeshoptDecoder 读取。累计约 8.2 MB。近景较密，帧率仍取决于设备和全园画质，不保证移动端 60 FPS。
- 幕墙是带介电反射和 clearcoat 的不透明玻璃，代表背后的遮阴室内；不构建透视室内。外置格栅有 68 cm 估算空腔。
- 42 个独立简化碰撞体覆盖塔楼、四组裙楼、屋顶上层平台、庭院环廊与庭院地面，不使用几十万三角面的装饰网格计算碰撞。碰撞随细节档位保持不变。
- 原有校园简化图书馆和通用门窗生成器已停用，防止重复立面和穿插。

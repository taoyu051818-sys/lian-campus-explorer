# 全园地形 v0.39.0

本批先解决建筑依托的连续地面：校园位于滨海低地，生活区后方接山坡，道路与楼群落在台地上。它是参考总图和全景的场景重建，未取得统一竣工高程网或测绘 DEM。

## 证据与估算

- 现有 `public/overall/parcels.png`：按北向及 1000 米比例尺沿用总图坐标；人工读取五处 223.0、210.2、189.1、190.4、110.9 米点高程。山峰间的坡形与沟谷为拟合，不等于等高线测量。
- 用户指定的 https://www.720yun.com/vr/5dejtgefzu6 「高空鸟瞰」场景：核对生活区后的连续林坡、滨海建筑前的低地与湿地，以及南侧山海关系。已在 Chrome 查看四个方向。资料展示的建设时间可能不一致。
- 海岸与山中湖轮廓参考总图，滨海过渡宽度参考全景作近似。湖面 8.4 米为场景设定；总图范围之外的低精度陆地只用于延续背景，不作为已测地物。
- 建筑仍使用现有米制和地块配准；本批没有把图面坐标冒称为统一测绘坐标。

## 地形与建筑如何衔接

`public/terrain/landform.json` 保存岸线、山脊、点高程、湖面与原有地形基线。`src/campus-terrain.ts` 组合山坡、沿海低地、道路走廊和建筑台地。核心校园继续使用同一张 20 米三角网，渲染和物理采样一致；外围约 80 米网格逐点对接核心边界，消除裁切边缘。

九处已精建 Blender 资产的建筑、铺装和种植包络外保留至少一圈完整地形单元，再平滑衔接新山坡。这些模型的局部地形已经烘焙，直接改变其脚下高程会使铺装、树木和入口悬空。因此本批锁定既有局部高差，不强行假设新的绝对建筑标高。以后取得测量资料时，应连同 GLB 景观和碰撞重新生成。新资产不应直接加入旧高程保护清单。

其余楼群建立整平台地；与既有保护区交接的地方抬高基础，并补可见、可碰撞的外露基座，避免地面进入首层或基础悬空。教学连廊、体育场及现有露台的相对高程保留。

道路、路肩、路口与普通步道按地形三角面裁切，内部点也贴合地面。山坡加入背景林冠覆盖；其数量和树种不代表现场树木调查。林冠不设逐树碰撞，地面仍有连续碰撞。

## 查看与重建

- `world.html?place=stadium&view=terrain` 或场景中的「山海地形」按钮。
- `npm run bake` 生成校园地形、台地、道路、外围地形、林冠和碰撞。
- `npm run test:terrain` 检查点高程、九处模型局部高程、道路内部贴地、道路坡度和楼体基础。
- `npm run test:materials` 检查全部材质映射、地形采样与上游来源完整性。
- `npm run test:physics` 检查 33 处到达点及现有楼梯、入口、连廊。
- `npm run build` 构建 Three.js WebGPU 运行版。

本批无需重新导出九处建筑 GLB。复现数据和作者工具均在仓库；浏览器验证记录另存于 `验证记录/webgpu-v0.39.0.json`。后续在生活二区精建时继续细化山脚道路、台地边坡与挡土关系。
